# 01 · agent views: results, 2026-11-07

**Verdict: check passed, stop not hit.** On both models, the projected view matched or beat the file as it is,
at 14% of its tokens.

Data: `repos.toml` (81 repos, 16 fields). 20 generated questions. Models `claude-haiku-5-5` (3 passes) and
`claude-sonnet-5-5` (1 pass), through `claude -p` with no tools. Token counts are Claude's own, from the usage
report, and include about 700 tokens of system prompt and question per call.

Token means are Haiku's; Sonnet's are within 5%.

## What it shows
- **What goes in beats how it's written.** The projected view gets 7.1× more correct answers per token than
  the file as it is, and 5.4× more than the best syntax.
- **TOON buys nothing over CSV on Claude:** 2% *more* tokens than CSV, accuracy within noise. Its published
  ~40% saving is measured against pretty-printed JSON.
- **Claude's tokenizer counts this data at about 1.6× the `o200k_base` proxy** (inferred from the toml-vs-view
  difference, not measured directly). The ratios between views hold; absolute estimates made with the proxy
  run low.
- **7 misses in all, all Haiku:** 5 on one list question (q15: active repos with no stop) and 2 off-by-a-few counts
  in the toml and csv views. Part of q15 is the data's fault: `homelab`'s stop field reads "none set: …", so a reader takes it as no stop.

## Limits
- `view` is told which fields the question needs. This measures the upper bound of projection; an agent
  choosing its own fields may pick wrong ones. That's the next run.
- One file, 20 mechanical questions, n = 60 and 20 per view. A difference of one or two answers is noise.
