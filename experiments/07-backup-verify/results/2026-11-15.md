| Case | Exit | Outcome |
|---|---|---|
| good backup, floor 5,000 rows, newest row under 600 s old | 0 | PASS 2/2 checks, 1.1 s |
| same backup, floor 6,000 | 1 | FAIL 1/2 checks; the row check failed, freshness passed |
| new snapshot with a truncated dump | 1 | load step raised (psql exit 3); recorded as a failed run with the error |

- History file got one JSON line per run (`ok`, duration, `error` on a throw): enough for an external alert.
- The "dead-man's switch" is `notify.heartbeat_url`, pinged only on success; a missed run alerts only if the receiving
  service (healthchecks-style) is set to expect it. Not exercised: it would call an outside URL.
- Not tested: Docker scratch-container mode (the one the README leads with), `pgbackrest`, a real encrypted repo with
  our SOPS key, a production-size dump, restore time at size.
- Freshness had to be written as a SQL check on the newest row; the tool has no built-in age check for restic snapshots.
